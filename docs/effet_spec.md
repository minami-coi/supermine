# Super Mine Sweeper --- 演出仕様

## 1. 目的と基本方針

本書は、マインスイーパー「Super Mine Sweeper」に追加する演出、スコア、コンボ、演出設定を定義する。
基本ゲームルールは別途定義されたゲーム仕様に従い、本書によって地雷判定・開封処理・勝敗判定を変更してはならない。

### コンセプト

-   テーマは「カオス・お祭り騒ぎ」。過剰な爆発、紙吹雪、光、巨大な文字、スコア表示でプレイヤーの高揚感を最高潮にすることを目的とする
  - とにかくプレイヤーの気持ちがアガることが大事。やりすぎなくらい演出してもよい
-   派手さを重視する一方、盤面の数字、旗、未開封マス、残り地雷数、操作ボタンは常に認識できるようにする。
-   通常操作は短く、連鎖は中規模、クリア・ゲームオーバーは大規模な演出にする。
-   演出が停止・失敗・無効化されてもゲーム進行に影響しないこと。

### 技術方針

-   UI: React + Vite
-   タイルや文字: React + CSSアニメーション
-   粒子・紙吹雪・爆発: Canvas
-   サーバー通信は行わない
-   ゲームロジック、スコア計算、演出選択、描画を分離する

## 2. 演出の優先順位と視認性

表示の優先順位は次のとおり。

1.  盤面と操作に必要な情報
2.  ゲーム状態
3.  スコア、コンボ、残り地雷数、経過時間
4.  演出エフェクト

エフェクトが盤面の上に表示されてもよいが、重要な情報を長時間隠してはならない。巨大なテキストやフラッシュは短時間で消す。大量のイベントは集約し、マスごとに巨大な演出を発生させない。

### 演出時間の目安

  演出                              初期目安
  -------------------------- ---------------
  タイルのポップ                 100〜180 ms
  スコア加算表示                 500〜800 ms
  通常の粒子                     300〜700 ms
  連鎖の波紋                     400〜900 ms
  コンボ文字                    600〜1000 ms
  地雷爆発のヒットストップ       100〜200 ms
  ゲームオーバーの主要演出      700〜1200 ms
  クリアの主要演出             1500〜2500 ms

これらは目安であり、通常プレイ中は演出の完了を待たずに操作を続けられること。クリア・ゲームオーバー後の入力可否は基本ゲーム仕様に従う。

## 3. 演出イベント

ゲーム操作処理は、状態更新結果とともに演出レイヤーが利用できるイベント情報を返す。演出側はイベントを視覚効果へ変換する。ゲームロジック側からCSSクラス名を直接指定しない。

推奨イベント:

-   `CELL_REVEALED`: マスが開いた
-   `CELLS_AUTO_REVEALED`: 連鎖などで複数マスが開いた
-   `FLAG_PLACED`: 旗を設置した
-   `FLAG_REMOVED`: 旗を解除した
-   `CHORD_TRIGGERED`: 数字マスの一括開封を実行した
-   `SCORE_CHANGED`: スコアが変化した
-   `COMBO_CHANGED`: コンボ数・倍率が変化した
-   `MINE_EXPLODED`: 地雷を開いてゲームオーバーになった
-   `GAME_CLEARED`: クリアした
-   `GAME_OVER`: ゲームオーバーになった

イベントには、種別、対象マス座標、今回開いたマスの一覧、スコア増減、更新後のコンボ数・倍率、ゲーム状態の変化など、演出判断に必要な最小限の情報を含める。イベントはゲーム状態を直接変更できないものとする。同一イベントの二重処理を避けるため、一意なイベントIDを利用してよい。

## 4. 操作別の演出

### 4.1 安全なマスを開く

-   タイルをわずかに縮めてから弾ませるポップアニメーション。
-   小さな星や円形粒子を数個発生させる。
-   数字は色分けするが、文字のコントラストと視認性を維持する。
-   加点時は `+10` などをタイル付近に浮かせる。
-   通常操作の演出は短くし、操作テンポを妨げない。
-   ゲーム状態が変化しない無効操作では演出を出さない。

### 4.2 旗の設置・解除

-   旗の設置時はアイコンを軽く跳ねさせる。
-   旗の解除時はアイコンを縮小して消す。
-   旗の設置・解除だけでは、対象マスが地雷かどうかを示す演出を出さない。
-   残り地雷数表示は即座に更新する。

**重要:**
標準ルールでは、旗を立てた瞬間にその旗が正しいかどうかをプレイヤーに知らせない。正しい地雷の特定に報酬を付ける場合は、ゲーム終了時の結果集計など、正誤を秘密裏に判定して知らせることのないタイミングで確定する。プレイ中に正解報酬を出す場合は、基本ルールの変更として別途明記する。

### 4.3 空白マスの連鎖展開

-   連鎖の起点から外側へ光の波紋を広げる。
-   自動開封されたタイルには短い時間差で小さなポップを適用してよい。
-   大量のマスが開いた場合は、個別アニメーションを抑え、波紋と集約したコンボ表示を中心にする。
-   表示例: `CHAIN x12`、`MASSIVE CHAIN!`
-   テキストは盤面を長時間覆わない。必要に応じて盤面上部や外側に表示する。

  自動開封マス数   演出
  ---------------- --------------------------------
  1〜3             小さなポップ、少量の粒子
  4〜9             波紋、中程度の粒子
  10以上           大きな波紋、コンボ文字、紙吹雪

境界値は実装後に調整してよい。

### 4.4 数字マスの一括開封

-   一括開封時は、起点となる数字マスを短く光らせる。
-   複数マスが開いた場合は、開封数に応じて連鎖展開と同様の演出を行う。
-   旗数が一致せず一括開封されなかった場合、控えめな反応を表示してよい。
-   一括開封で地雷を開いた場合は、通常の開封演出よりゲームオーバー演出を優先する。

### 4.5 正しい地雷の特定

-   金色・黄色の光、星、紙吹雪などで祝福する。
-   表示例: `NICE!`、`PERFECT!`、`UNSTOPPABLE!`
-   スコア加算がある場合は大きな数値で示す。
-   コンボ倍率に応じて演出を強める。
-   地雷であることがゲームロジック上確定している場合に限り、正解演出を発生させる。旗を立てた瞬間に地雷の有無を照合してはならない。

### 4.6 地雷を踏む

-   100〜200 ms程度の短いヒットストップ。
-   赤・橙・白のフラッシュ、爆発、煙、破片。
-   短い画面揺れと巨大な文字（例: `BOOOOOOM!!!`）。
-   地雷の位置と旗の正誤を表示する。
-   結果画面にはスコア、経過時間、最大コンボなどを表示する。
-   同じ操作で爆発演出とゲームオーバー演出が二重に再生されないようにする。

### 4.7 クリア

-   紙吹雪、花火、星、カラフルな光の粒子を大量に表示する。
-   表示例: `YOU ARE A LEGEND!`、`ABSOLUTE MADNESS!`
-   スコア、クリアタイム、最大コンボをまとめて表示する。
-   ハイスコア更新時は特別な演出を行う。
-   クリア演出はゲーム内で最も華やかな演出とする。
-   結果表示は演出終了後も残す。

## 5. スコア仕様

初期値は次のとおり。実装後のプレイテストで調整してよい。

  アクション               基本点
  ------------------ ------------
  安全なマスを開く            +10
  正しい地雷の特定           +100
  クリア                     +500
  誤った旗                      0
  地雷を踏む           追加点なし

-   連鎖開封で自動的に開いた安全なマスにも1マスあたり+10点を加算する。
-   同じマスに複数回加点してはならない。
-   地雷の正解報酬は、標準ルールを維持する場合、ゲーム終了時に正しい旗を集計する方式とする。プレイ中に秘密裏に正解判定して報酬を出す仕様へ変更する場合は、ゲームルール側にも明記する。
-   クリアボーナスはクリア判定時に一度だけ加算する。
-   内部スコアは即時に確定し、表示アニメーションの遅延・中断によって変化しない。

## 6. コンボ仕様

コンボは、プレイヤーが行った有効な操作を単位として管理する。自動連鎖で開いた各マスを別々のコンボ操作として数えない。

-   コンボ対象候補は、安全なマスを開く操作と、有効な旗の設置・解除操作とする。
-   状態が変わらない無効操作はコンボを増やさない。
-   前回のコンボ対象操作から2秒以内に次の対象操作が発生したらコンボを継続する。
-   2秒を超えたらコンボをリセットし、新しいコンボを開始する。
-   ゲーム終了時にコンボを終了する。
-   連鎖展開のスコアは開いたマス数に応じて加算するが、コンボ数はプレイヤー操作単位で扱う。

  コンボ数     スコア倍率
  ---------- ------------
  1〜4                 ×1
  5〜9                 ×2
  10〜19               ×3
  20以上               ×5

倍率はスコア加算にのみ適用し、地雷配置や勝敗判定には影響させない。同一の加点に倍率を二重適用しない。

クリック時のフラグやスコア演出は、1回ごとに大きくする。また、コンボ数も表示する

### 表示

-   コンボ数が増えたらカウンターを短く拡大して戻す。
-   倍率が上がったら通常更新より強い演出を行う。
-   コンボが途切れたらカウンターを縮小して消すか、0に戻す。
-   表示例: `COMBO x12`。
-   表示は盤面を長時間覆わない。
-   コンボ状態はゲームロジック側で更新し、アニメーション完了を待たない。

## 8. Canvasパーティクル

### 対象

-   星・円形の粒子
-   紙吹雪
-   爆発の破片
-   光の波紋
-   煙や光の粒子

盤面や文字などのUIはReact/CSSで描画し、Canvasは演出専用とする。ゲーム状態をCanvas内に複製せず、ゲーム判定のためにCanvasのピクセル情報を参照しない。

### 座標・リサイズ

-   CSS上のサイズとCanvas内部の描画解像度を同期する。
-   デバイスピクセル比を考慮しつつ、必要に応じて描画解像度に上限を設ける。
-   盤面スクロールやウィンドウリサイズに対応する。
-   必要に応じて盤面座標を画面座標へ変換する。

### 負荷対策

-   同時に存在する粒子数に上限を設ける。
-   連鎖時に各マスから大量の粒子を生成しない。
-   画面外の粒子を早めに破棄する。
-   `requestAnimationFrame` を利用し、不要時はループを停止する。
-   コンポーネント破棄時にアニメーションループやイベントリスナーを解除する。
-   非表示タブやゲーム終了後に不要なアニメーションを継続しない。
-   低性能端末でもゲーム操作のレスポンスを優先する。

## 9. 画面揺れ・フラッシュ

-   画面揺れは地雷爆発や大規模な連鎖など重要なイベントに限定する。
-   揺れの対象は表示レイヤーとし、盤面データを変更しない。
-   連続発生時は強さを合成するか、一定時間内の再発生を制限する。
-   フラッシュは短くし、強い白色点滅を連続させない。
-   重要な数字や操作ボタンが長時間見えなくならないようにする。
-   動きの軽減設定が有効なら、揺れ・ヒットストップ・大きなズームを無効化または縮小する。

## 10. 重複抑制とイベント優先順位

演出の優先順位:

1.  `GAME_OVER` / `GAME_CLEARED`
2.  `MINE_EXPLODED`
3.  コンボ倍率上昇・正しい地雷の特定
4.  大規模な連鎖展開
5.  通常のマス開封・旗操作

-   ゲーム終了演出中は低優先度の新しい演出を抑制・集約する。
-   イベントID等を利用して同一イベントの二重処理を防ぐ。
-   演出キューを利用する場合、通常演出を長いキューに積み上げない。古い低優先度演出は破棄または集約する。
-   盤面の状態更新は演出キューやアニメーション完了を待たずに確定する。
-   ゲームの終端状態は一度だけ確定し、クリア演出とゲームオーバー演出が重複しないようにする。

## 11. 設定とアクセシビリティ

-   動きの軽減設定を提供し、OS/ブラウザの `prefers-reduced-motion`
    を尊重する。
-   演出を軽減しても、開封状態、旗、勝敗、スコア等の情報は失われない。
-   色だけで状態を伝えず、数字・アイコン・形状を併用する。
-   フラッシュを過度に強く・頻繁にしない。
-   設定変更はゲームをリセットせず反映できることを基本とする。

## 12. 推奨ディレクトリ構成

``` text
src/
├── effects/
│   ├── EffectLayer.jsx      # テキストやDOM/CSS演出
│   ├── ParticleCanvas.jsx   # Canvas描画
│   ├── particleSystem.js    # 粒子の生成・更新・描画
│   ├── effectRules.js       # イベントから演出への変換
│   └── useEffects.js        # イベント購読とクリーンアップ
├── game/
│   ├── scoring.js           # スコア計算
│   └── combo.js              # コンボ計算
└── styles/
    └── effects.css
```

ファイルは実装上の都合で統合・分割してよい。ただし、次の責務は分離する。

-   ゲームロジック: 操作の有効性、盤面状態、勝敗を決める
-   スコア・コンボ: 加点と倍率を決める
-   演出ルール: イベントに対して再生する演出を決める
-   描画: CSSやCanvasで演出を表示する

## 13. テスト要件

-   演出を無効化してもゲームロジックの結果が変わらない。
-   同一イベントが二重に処理されない。
-   ゲームオーバー演出とクリア演出が二重に再生されない。
-   大量の連鎖演出中も盤面操作が遅延しない。
-   表示アニメーションと内部スコアが一致する。
-   コンボ倍率が仕様どおりに変化する。
-   動きの軽減設定で揺れ・ズーム・フラッシュが軽減される。
-   リサイズやスクロール後もパーティクル位置が大きくずれない。
-   コンポーネント破棄後にCanvasループやイベントリスナーが残らない。
-   初級・中級・上級で、演出による操作遅延が発生しない。

## 14. 完了条件

-   [ ] 通常のマス開封と旗操作に短い演出がある。
-   [ ] 連鎖展開に規模に応じた演出がある。
-   [ ] 地雷爆発とクリアに専用の大規模演出がある。
-   [ ] スコアとコンボが仕様どおりに計算・表示される。
-   [ ] 動きの軽減設定に対応する。
-   [ ] 演出が盤面の視認性を長時間妨げない。
-   [ ] 演出処理がゲームロジックから分離されている。
-   [ ] 大量の演出中も操作レスポンスが維持される。
-   [ ] 演出の有無で盤面状態や勝敗が変わらない。

## 15. 基本ゲーム仕様との整合性

基本ゲーム仕様と本書に矛盾がある場合、基本ゲーム仕様を優先する。

-   旗を立てた瞬間に地雷の正誤をプレイヤーへ知らせない。
-   演出のために地雷配置や勝敗判定を変更しない。
-   演出完了を待ってゲーム状態の更新を遅らせない。
-   ゲーム終了後の操作可否は基本ゲーム仕様に従う。
-   スコアやコンボを導入しても、マインスイーパーの推理を不当に有利・不利にしない。
