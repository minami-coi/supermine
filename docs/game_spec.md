# SuperMineSweeper --- 基本ゲーム仕様

## 1. 目的と対象範囲

本書は、ブラウザ上で動作するマインスイーパー「Super Mine Sweeper」の基本ゲームロジックを定義する。

この段階では、標準的なマインスイーパーとして正しく遊べることを優先する。派手なアニメーション、パーティクル、画面揺れ、効果音、演出用コンボ表示などは対象外とし、後続の演出設計で別途定義する。

### 1.1 技術方針

-   フロントエンド: React + Vite
-   言語: JavaScript
-   実行環境: ブラウザ
-   サーバー通信: 不要
-   ゲームロジックは React コンポーネントや DOM に依存しない JavaScript
    モジュールとして実装する。

### 1.2 基本方針

-   ルールは一般的なマインスイーパーに準拠する。
-   ゲームロジックと画面表示を分離する。
-   同じゲーム状態と同じ操作に対して、同じ結果が得られるようにする。
-   演出の有無が、地雷判定・勝敗判定・スコアなどのゲームロジックに影響しない設計にする。
-   まず基本機能を完成させ、演出機能は後から追加する。

## 2. ゲームルール

### 2.1 盤面

列数:8
行数:8
地雷数:20

### 2.2 マスの状態

各マスは、少なくとも次の情報を持つ。

-   `hasMine`: 地雷があるか
-   `adjacentMines`: 周囲8マスにある地雷数（0〜8）
-   `isRevealed`: 開封済みか
-   `isFlagged`: 旗が立っているか

マスの状態は必要に応じて追加してよいが、表示上の状態とゲームロジック上の状態を混同しない。

### 2.3 ゲーム全体の状態

ゲーム全体は、少なくとも次の情報を管理する。

-   盤面
-   ゲーム状態
-   旗の数
-   開封済みマス数
-   経過時間
-   最初のマスが開封されたかどうか

ゲーム状態は次のいずれかとする。

-   `ready`:
    ゲーム開始前。盤面は生成済みでもよいが、地雷配置は確定していない。
-   `playing`: プレイ中
-   `won`: クリア
-   `lost`: ゲームオーバー

状態遷移は原則として `ready → playing → won/lost` とする。`won` または
`lost` からプレイ状態に戻す場合は、新しいゲームを開始する。

### 2.4 地雷配置と初回開封

-   新しいゲームを開始した時点では、地雷配置を未確定にしてよい。
-   プレイヤーが最初に開封したマスには地雷を配置しない。
-   初回開封後、残りのマスから指定数の地雷をランダムに配置し、各マスの
    `adjacentMines` を計算する。
-   初回開封したマスの周囲まで安全にする仕様は必須ではない。安全なのは最初にクリックしたマスのみ。
-   初回開封が空白マスの場合は、通常の連鎖開封ルールを適用する。
-   地雷配置は盤面サイズと地雷数に矛盾がないことを検証してから実行する。

### 2.5 マスを開く

-   未開封かつ旗が立っていないマスを開けられる。
-   すでに開封済みのマスを開く操作は何もしない。
-   旗が立っているマスを開く操作は何もしない。
-   地雷のないマスを開くと、数字を表示する(0の場合は数字は表示しない、ただし未開封の場合と区別できるようにする)
-   地雷のあるマスを開くとゲームオーバーになる。
-   ゲーム状態が `won` または `lost`
    の場合、マスを開く操作を受け付けない。
-   最初の開封では「初回開封」のルールを適用してから、開封処理を続ける。

### 2.6 空白マスの連鎖開封

開封したマスの `adjacentMines` が `0`
の場合、周囲8マスを自動的に開く。自動開封先がさらに `0`
の場合は、その周囲にも同じ処理を繰り返す。

-   連鎖開封では、地雷のあるマスを開かない。
-   旗が立っているマスは自動開封しない。
-   開封済みマスを何度も処理しない。
-   再帰の深さによる問題を避けるため、必要に応じてキューやスタックを使った反復処理で実装する。
-   連鎖開封の結果、複数のマスが開いた場合も、各マスの状態と開封済みマス数を正しく更新する。

### 2.7 旗の設置・解除

-   未開封のマスに旗を設置できる。
-   旗が立っている未開封マスに再度操作すると、旗を解除する。
-   開封済みマスには旗を設置できない。
-   旗の数に上限は設けない。地雷数より多く旗を立てることもできる。
-   残り地雷数表示は `地雷数 - 旗の数` とする。負の値になってもよい。
-   旗を立てた時点では、そのマスが本当に地雷かどうかを判定してプレイヤーに知らせない。
-   ゲーム終了後は旗の設置・解除を受け付けない。

### 2.8 数字マスの周囲を一括開封（Chord）

数字が表示されている開封済みマスに対して一括開封操作を行える。

-   対象マスの `adjacentMines`
    と、周囲8マスに立っている旗の数が一致する場合、周囲の未開封かつ旗のないマスを開く。
-   旗の数が一致しない場合は何もしない。
-   旗の数が一致していても、旗の位置が誤っていれば地雷を開いてゲームオーバーになる可能性がある。
-   ゲーム終了後は操作を受け付けない。

UIでは、PCのクリック操作とモバイルのタップ操作が混同されないよう、一括開封の入力方法を明確にする。具体的な入力割り当てはUI仕様で定義する。

### 2.9 クリア条件

次の条件を満たした時点でクリアとする。

-   地雷のないマスがすべて開封されている。

旗をすべて正しい位置に立てることは必須条件ではない。安全なマスをすべて開封すれば、地雷に旗を立てていなくてもクリアとなる。

クリア判定は、マスを開封した処理と連鎖開封処理が完了した後に行う。

### 2.10 ゲームオーバー

-   地雷のあるマスを開いた時点で `lost` に遷移する。
-   ゲームオーバー後は、開封・旗設置・旗解除・一括開封を受け付けない。
-   結果表示用に、地雷の位置とプレイヤーが立てた旗の状態を参照できるようにする。
-   地雷を踏んだマス、正しい旗、誤った旗などの見せ方は画面表示仕様で定義する。

## 3. 時間計測

-   経過時間は、最初のマスを開封してゲーム状態が `playing`
    になった時点から計測する。
-   `ready` の間は計測しない。
-   `won` または `lost` になった時点で計測を停止する。
-   表示用の更新頻度と実際の経過時間を分離し、タイマーの呼び出し回数を経過時間として扱わない。
-   実時間はタイムスタンプの差分から計算する。
-   表示形式は `分:秒` とする。小数点以下の表示は必須ではない。

## 4. スコアとコンボ

この段階では、スコアとコンボは**実装しない**。ゲームロジックの正確性を優先し、演出設計を追加する段階で仕様を定義する。

将来追加しやすいよう、盤面操作の結果を呼び出し側が把握できる戻り値にすることは推奨する。たとえば、今回開いたマスの一覧、旗を設置・解除したマス、ゲーム状態の変化などを返す。

## 5. 画面要件

基本ゲームを操作できる最低限の画面を実装する。

-   新しいゲーム／リスタート操作
-   盤面
-   残り地雷数（地雷数 - 旗の数）
-   経過時間
-   クリア／ゲームオーバー時の結果表示

この段階では、派手な演出、パーティクル、効果音、画面揺れ、コンボ表示、アニメーションは実装しない。タイルの状態変化が分かる程度のシンプルなCSSは使用してよい。

## 6. 入力と対応環境

### 6.1 PC

-   左クリック: 未開封マスを開く。
-   右クリック: 未開封マスの旗を設置・解除する。
-   右クリックによるブラウザのコンテキストメニューは、ゲーム盤面上では表示しない。
-   数字マスの一括開封操作を用意する。入力方法は実装時に一貫した方式を採用し、READMEに記載する。

### 6.2 スマートフォン

-   タップ: マスを開く。
-   旗モード: 有効時のタップで旗を設置・解除する。
-   旗モードの有効・無効が画面から明確に分かるようにする。
-   一括開封は、モバイルでも実行できる明示的な操作方法を用意する。
-   長押しを採用する場合は、スクロールや通常タップとの誤認識を避ける。

### 6.3 レスポンシブ表示

-   盤面が画面幅を超える場合は、タイルを極端に小さくせず、必要に応じて盤面領域をスクロール可能にする。
-   タイルのクリック領域と数字が認識できる大きさを保つ。
-   上級盤面では横スクロールを許容する。

## 8. ゲームロジックのインターフェース方針

関数名や引数は実装時に調整してよいが、責務は次のように分ける。

-   `createBoard(config)`: 盤面の初期状態を作成する。
-   `placeMines(board, config, safeCell)`:
    指定数の地雷を配置する。初回開封マスは配置対象から除外する。
-   `calculateAdjacentMines(board)`: 各マスの周囲の地雷数を計算する。
-   `revealCell(state, row, col)`:
    マスを開き、必要に応じて連鎖開封と勝敗判定を行う。
-   `toggleFlag(state, row, col)`: 旗を設置または解除する。
-   `chordCell(state, row, col)`: 数字マスの周囲を一括開封する。
-   `checkWin(state)`: クリア条件を判定する。
-   `createNewGame(difficulty)`: 新しいゲーム状態を作成する。

ゲーム操作関数は、状態を直接変更するよりも、新しい状態と操作結果を返す方式を優先する。これにより、Reactの状態更新や自動テストが容易になる。

## 9. テスト要件

ゲームロジックのテストは、DOMやブラウザ描画に依存せず実行できるようにする。

### 9.1 盤面生成

-   地雷数が設定値と一致する。
-   地雷配置後の各マスの数字が周囲の地雷数と一致する。
-   初回開封マスには地雷が配置されない。
-   同じマスが重複して地雷配置対象として扱われない。

### 9.2 開封

-   安全なマスを開くと開封済みになる。
-   地雷を開くとゲームオーバーになる。
-   旗の立ったマスは通常の開封操作では開かない。
-   開封済みマスへの開封操作で状態が壊れない。
-   数字が0のマスから安全な隣接マスが連鎖開封される。
-   連鎖開封で地雷や旗の立ったマスを誤って開かない。

### 9.3 旗

-   旗を立てると旗の数が1増える。
-   旗を解除すると旗の数が1減る。
-   開封済みマスには旗を立てられない。
-   地雷数を超えて旗を立てられる。
-   旗の正誤を、設置時点でプレイヤーに公開しない。

### 9.4 一括開封と勝敗

-   周囲の旗数が数字と一致すると一括開封が実行される。
-   旗数が一致しない場合は何も開かない。
-   誤った旗によって地雷を開いた場合はゲームオーバーになる。
-   すべての安全なマスを開くとクリアになる。
-   地雷に旗を立てていなくても、安全なマスがすべて開いていればクリアになる。
-   ゲーム終了後の操作で状態が変化しない。

### 9.5 状態と時間

-   新しいゲーム開始時に盤面・旗数・時間・勝敗状態が初期化される。
-   プレイ開始前に時間が進まない。
-   クリアまたはゲームオーバー後に時間が進まない。
-   難易度変更で新しい盤面が作成される。
-   連鎖開封や一括開封でクリア判定が複数回実行されても、状態が不正にならない。

## 10. 完了条件

次のすべてを満たしたら、基本ゲームロジックの実装完了とする。

-   [ ] 初級・中級・上級でゲームを開始できる。
-   [ ] 初回開封マスに地雷がない。
-   [ ] 数字が正しく計算される。
-   [ ] マスの開封と空白マスの連鎖開封が正しい。
-   [ ] 旗を設置・解除でき、残り地雷数が正しい。
-   [ ] 数字マスの一括開封が動作する。
-   [ ] クリアとゲームオーバーが正しく判定される。
-   [ ] 終了後の操作が無効になる。
-   [ ] 経過時間が正しく開始・停止する。
-   [ ] PCとスマートフォンで基本操作ができる。
-   [ ] ゲームロジックの自動テストが用意され、成功する。
-   [ ] 派手な演出や効果音に依存せず、ゲームを最後までプレイできる。
